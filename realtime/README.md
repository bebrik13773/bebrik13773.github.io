# Realtime-сервер «Дикий Лес» (РТ-01)

Отдельный Node.js-процесс для позиций, эмодзи, чата и событий. **Ничего не решает** и **никогда не ходит в PHP** (InfinityFree пускает только браузеры). Источник правды — PHP + MySQL. Схема: `Код/docs/WILD_FOREST_PLAN.md`, раздел 15.

Папка лежит в корне репозитория, а не в `Код/`, чтобы FTP-деплой не заливал её на InfinityFree.

## Что есть сейчас (РТ-01)
- `GET /health` — JSON: `build` (SHA коммита), `uptime_s`, `connections`, `rss_mb`, `tls`.
- WebSocket на том же порту: при подключении приходит `{"t":"hello",...}`, на `{"t":"ping","c":N}` отвечает `pong`.
- Принимает только `Origin` игры (`https://bober-api.gt.tc`) и `localhost`; лимит соединений 150; сообщение до 4 КБ.
- Лимит памяти `--max-old-space-size=120`, обрыв «тихих» соединений пингом раз в 25 с.

## Переменные окружения
| Переменная | По умолчанию | Смысл |
|---|---|---|
| `PORT` | 8080 | порт (платформа обычно задаёт сама) |
| `BUILD_SHA` | dev | SHA коммита (в Docker — `--build-arg BUILD_SHA=...`) |
| `WF_ORIGINS` | игра + localhost | разрешённые Origin через запятую |
| `WF_MAX_CONN` | 150 | потолок соединений |
| `WF_TLS_CERT`, `WF_TLS_KEY` | пусто | пути к сертификату и ключу: тогда сервер сам отдаёт HTTPS/wss |

## Запуск и тест
```bash
cd realtime
npm install
npm test          # /health, hello, Origin, лимит соединений
npm start
```

## Деплой (платформа умеет Git, Docker и ZIP)
1. **Git**: указать репозиторий, папку `realtime`, команду запуска `npm start`.
2. **Docker**: `docker build --build-arg BUILD_SHA=$(git rev-parse --short HEAD) -t wf-realtime realtime`.
3. **ZIP**: `server.js`, `package.json`, `package-lock.json` (+ `npm ci --omit=dev` на платформе).

## TLS: нужен `wss://` (страница игры на HTTPS)
**Вариант А (проще, 99 ₽ за 30 дней).** Тариф Lite даёт домен платформы с готовым HTTPS: сертификаты не нужны, `WF_TLS_*` не задаём, платформа терминирует TLS и проксирует на `PORT`.

**Вариант Б (бесплатно): DuckDNS + Let's Encrypt** (выбран владельцем для бесплатного тарифа).
1. На duckdns.org завести поддомен `имя.duckdns.org`, указать IP сервера, сохранить токен.
2. Выпустить сертификат через **DNS-проверку** (порт 80 не нужен): на любом компьютере
   ```bash
   export DuckDNS_Token=ТОКЕН
   acme.sh --issue --dns dns_duckdns -d имя.duckdns.org
   ```
3. Положить `fullchain.cer` и ключ на сервер, задать `WF_TLS_CERT` и `WF_TLS_KEY`. Продление раз в 60–90 дней тем же способом (автоматизируем в РТ-08).
4. Платформа должна пробрасывать внешний **443** на `PORT` приложения. Если открыт только случайный порт, `wss://имя:порт` тоже работает, но мобильные операторы иногда режут нестандартные порты, поэтому проверять с телефона в мобильной сети.

Let's Encrypt на голый IP не выдаёт сертификат в обычном режиме, поэтому нужен поддомен.
